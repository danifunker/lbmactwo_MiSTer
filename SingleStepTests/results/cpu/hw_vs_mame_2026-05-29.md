## Divergence buckets (vs MAME oracle)

| Bucket | Count | Root cause (not a CPU semantics difference) |
|---|---:|---|
| `ccr_only`  | 11 | Undefined CCR bits on DIVS/DIVU/CMP2/CHK2/NBCD/ABCD; one ORI #imm,CCR capture-timing artifact. PRM leaves these bits undefined — both silicon and MAME pick legal values that just disagree. |
| `flag_only` | 10 | `MOVE.L ([…A6…])` / `MOVE (xxx).L=$1820` reads. The load executed correctly; bench scratch at `$1820` isn't pre-seeded with the oracle's payload pattern (`0xCAFEF00D` etc.), so the read returns the actual scratch bytes (`0x40800D98`). |
| `dreg_diff` | 15 | `PEA (…A6…)`, `EXG D,A`, `MOVE.L A6,D0` return the address of scratch — different absolute base on hw vs MAME. `MOVEC VBR/SFC/DFC/CACR` returns live machine state (bench installs its own vector table). |
| `ram_diff`  |  4 | `MOVE …,(xxx).L=$1820` writes outside the 64-byte scratch window the dumper captures; MOVEM of mixed D/A masks writes A-reg values (same root cause as `dreg_diff`). |
| `unknown`   |  3 | `MOVES.{B,W,L} D0,(A1)` — privileged, traps to a privilege-violation handler that clobbers A1 before the snapshot. |
